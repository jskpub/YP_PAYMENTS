# 지원금 Rule 영역 — PRD / IA / 화면별 상세 기획서

> 범위 안내: 화면별 상세 기획은 **지원금·결제 로직이 관여하는 부분만** 다룹니다. 추천도서/개인도서 목록·상세의 일반 화면 기획(검색, 필터, 정렬, 도서정보 레이아웃 등)은 별도 작업자 담당이므로 이 문서에서는 영역 표시 수준으로만 언급합니다.

# 1. PRD — 지원금 Rule Engine

## 1.1 개요

**목적**: B2B 기업 임직원 독서 지원 프로그램에서, 추천도서와 개인도서 구매 시 회사 지원금을 자동으로 계산·적용하고, 월 단위로 지원 한도를 관리하는 기능을 제공한다.

**우선순위**: P0 (핵심 비즈니스 로직, B2B 플랫폼 다음으로 착수)

**스코프에 포함**: 지원금 계산 로직, 월 1권 제한 관리, 지원금 사용 현황 조회
**스코프에서 제외**: 복합결제 처리(별도 영역), 정산자료 생성(이번 프로젝트 범위 외)

## 1.2 대상 화면 (4개, wbs-작업-관례 기준)
- 추천도서 목록
- 개인도서 목록/검색
- 도서 상세
- 나의 지원금

## 1.3 지원금 정책

### 추천도서
| 항목 | 내용 |
|---|---|
| 지원율 | 판매금액 100% |
| 월간 제한 | 월 1권 |
| 도서 유형 | 종이도서만 |
| 직원 결제 | 0원 |

### 개인도서
| 항목 | 내용 |
|---|---|
| 지원율 | MIN(판매금액 × 50%, 10,000원) |
| 월간 제한 | 월 1권 |
| 도서 유형 | 종이도서 또는 전자도서 선택 |
| 직원 결제 | 판매금액 − 회사지원금 |

**계산식**
```
추천도서: subsidyAmount = sellingPrice, employeePayment = 0
개인도서: subsidyAmount = MIN(sellingPrice × 0.5, 10000)
          employeePayment = sellingPrice - subsidyAmount
```

**추천도서+개인도서 동시 신청**: 정책 미확정 (원문 §4에서도 "정책에 따라 통제"로만 명시, 요구사항_정리.pdf 회신에서도 "월/분기/반기 기준 검토 중"이라고만 답변됨) → **개발 착수 전 필수 확정 항목**

## 1.4 월 1권 통제 로직

- 리셋 주기: 매월 1일 자동 리셋 (고객사 계약일 기준 유연성은 별도 검토)
- 미사용분 이월 없음, 통계만 기록
- 환불 시 지원 한도 복원

**Ledger 예시**
| 직원 | 월 | 추천도서 | 개인도서 | 지원금 | 직원부담 |
|---|---|---|---|---|---|
| A | 9월 | O | X | 18,000 | 0 |
| B | 9월 | X | O | 10,000 | 12,000 |
| C | 9월 | O | O | 정책 미확정 | - |

## 1.5 Rule Engine 구현 방향

단순 쿠폰 방식이 아닌 **정책 엔진**으로 개발 → B2B 기업별 정책 변경 시 재개발 없이 관리자가 정책값만 수정 가능하도록 설계.

## 1.6 예외/에러 케이스
- 월 지원 한도 소진 시 안내
- 지원금 계산 실패 시 재시도
- 품절/재입고 도서의 지원금 재계산
- 환불 시 지원금 + 월 한도 동시 복원

## 1.7 미확정 항목 (착수 전 확인 필수)
- [ ] 추천+개인도서 동시 신청 시 통제 정책
- [ ] 월 지원한도 리셋 기준의 고객사별 유연성 여부
- [ ] 환불/취소 시 지원금 환수 기준 (요구사항_정리.pdf 회신이 Rule Engine 설계에 충분한지 재검토 필요)

# 3. 화면별 상세 기획서 (지원금/결제 관련 영역만)

## 3.1 추천도서 목록

**일반 화면 영역** (별도 담당): 도서 카드, 필터, 정렬, 페이지네이션 등 — 본 기획 범위 아님

**지원금 관련 요소** (본 기획 범위)
- 도서 카드에 "지원금 100%" 배지 표시 — 판매금액과 무관하게 고정 문구
- 이 화면 자체에는 계산 로직 없음 (금액 계산은 상세 화면에서 발생)

## 3.2 추천도서 상세

**일반 화면 영역** (별도 담당): 도서 이미지, 기본정보, 도서소개, 추천사유 등

**지원금 관련 요소** (본 기획 범위)

**표시 로직**
```
도서가격 100% = 회사지원금
직원부담금 = 0원 (고정)
```

| 판매금액 | 회사지원 | 직원부담 |
|---|---|---|
| 15,000 | 15,000 | 0 |
| 20,000 | 20,000 | 0 |
| 30,000 | 30,000 | 0 |

**월 1권 제한 체크 (구매 버튼 클릭 전 검증)**
```
추천도서 선택 → 월 1권 구매 가능 여부 확인
  ├─ 가능 → 회사 100% 지원 적용 → 구매 프로세스 진행
  └─ 불가 → 팝업 노출, 진행 차단
```

**표시 요소**
- 지원금 정보 블록: "회사 지원금 100% 적용" / 도서가격 / 직원부담(0원, 강조 표시)
- 월 1권 잔여 여부 안내 (신청 가능/이미 신청함)
- [구매하기] 버튼 — 클릭 시 월 1권 체크 선행

**팝업/예외**
- 월 1권 소진: "이미 이번 달 추천도서를 신청하셨습니다" → 구매 진행 차단
- 신청기간 만료(있을 경우): "신청 기간이 종료되었습니다"
- 지원금 계산/조회 오류 → 재시도

> ⚠️ 팝업 문구는 추정치, 원문에 확정 문구 없음 — 확인 필요

## 3.3 개인도서 검색/목록

**일반 화면 영역** (별도 담당): 검색, 카테고리/가격대/도서유형 필터, 정렬, 도서 카드 레이아웃 등

**지원금 관련 요소** (본 기획 범위)
- 도서 카드마다 **예상 지원금 실시간 표시**: "B2B 지원: MIN(가격×50%, 10,000원)원"
- 계산은 상세와 동일한 공식 적용, 목록 단계에서는 참고용 수치로만 노출 (실제 확정은 상세/장바구니에서)

## 3.4 개인도서 상세

**일반 화면 영역** (별도 담당): 도서 이미지, 기본정보, 설명, 공개 서평/평점

**지원금 관련 요소** (본 기획 범위 — 핵심)

**종이책/전자책 선택에 따른 재계산**
- 유형 선택 탭 전환 시 아래 계산 블록 즉시 재계산

**지원금 계산 로직**
```
subsidyAmount = MIN(sellingPrice × 0.5, 10000)
employeePayment = sellingPrice - subsidyAmount
```

| 도서가격 | 회사지원 | 직원부담 |
|---|---|---|
| 10,000 | 5,000 | 5,000 |
| 16,000 | 8,000 | 8,000 |
| 18,000 | 9,000 | 9,000 |
| 20,000 | 10,000 | 10,000 |
| 30,000 | 10,000 | 20,000 |
| 40,000 | 10,000 | 30,000 |

**지원금 계산 결과 표시 블록**
```
도서 가격         XX,000원
─────────────────────
회사 지원금       XX,000원
직원 부담금       XX,000원
─────────────────────
월 남은 지원금    XX,000원 (진행률 바)
```

**월 1권 제한 체크**
- [장바구니 추가] / [바로구매] 클릭 시 월 1권 잔여 여부 검증
- 지원금 소진 상태면 액션 차단 + 팝업

**팝업/예외**
- 지원금 소진: "이 달 지원금을 모두 사용하셨습니다" → 장바구니/구매 진행 차단
- 지원금 계산 오류(재시도)
- 품절 도서 알림 (지원금 계산과 무관, 참고 표시만)

## 3.5 나의 지원금 (마이페이지 내) — 지원금 영역 전체가 본 기획 범위

**목적**: 이번 달 지원금 사용 현황 확인

**구성 요소**
- 이번 달 지원 한도 / 사용액 / 남은액 / 사용률 바
- 추천도서 신청 여부(O/X) + 사용 지원금
- 개인도서 신청 여부(O/X) + 사용 지원금 + 직원부담금
- 월별 이력 테이블 (월 / 추천도서 / 개인도서 / 지원금 / 직원부담)

**예외 처리**
- 지원금 조회 실패(재시도)

## 3.6 장바구니 (복합결제 영역 — 지원금 표시 관여)

**지원금 관련 요소**
- 각 도서별: 도서가격 / 회사지원금 / 직원부담금 3단 표시
- 합계: 총 도서가격, 회사 지원금 합계, **직원 결제액 합계(강조)**
- 지원금 안내 배너: "OO,OOO원의 B2B 기업 지원금이 적용되었습니다"
- 월 한도 초과 시 팝업 노출 및 결제 진행 차단

**예외**
- 한도 초과: "월 지원금 한도를 초과했습니다"
- 지원금 재계산 오류(재시도)

## 3.7 결제 페이지 (복합결제 핵심)

**지원금/결제 관련 요소**

**복합결제 구조**
```
도서금액             25,000원
회사 지원금          10,000원  (자동 차감)
직원 결제금액        15,000원  (카드 결제 대상)
──────────────────────
최종 결제액          15,000원  ⭐ 강조
```

**결제 프로세스**
```
상품 선택 → 지원금 자동 계산 → 회사 지원금 차감(DB) → 직원 부담금 계산 → 직원 결제(PG) → 주문 완료 (1개 Order ID로 통합관리)
```

**표시 요소**
- 주문 요약: 도서별 지원금/부담금 내역 + 합계
- "직원이 결제할 금액: OO,OOO원" 강조 표시
- 결제수단 선택은 직원 부담금에 한함

**미확정 — 개발 착수 전 확인 필수**
- 기존 영풍문고 PG에서 단일 주문 2개 결제처(회사+직원) 지원 가능 여부
- 결제수단 종류(원문 미기재)

## 3.8 주문완료 (지원금 내역 노출)

**지원금 관련 요소**
- 주문 내역에 도서별 회사지원금/직원결제액 표시
- 지원금 사용 요약: "회사 지원금 사용: XX,000원 / 월 지원금 남은액: XX,000원"

## 3.9 환불/취소 (지원금 환수 — 미확정 핵심 이슈)

**지원금 관련 요소**

**환불 처리 로직**
```
원 구매: 20,000원 (회사 10,000 + 직원 10,000)
환불 시:
  회사 지원금 10,000원 복원
  직원 결제금 10,000원 환불
  월 1권 한도 복원 (재신청 가능 상태로 전환)
```

**미확정 — 최우선 확인 필요**
- 환불 시 회사 지원금 환수 기준 (원문 §8: "회사 지원금을 어떻게 회수할 것인지 필요함"이라고만 서술, 확정 로직 없음)
- 부분환불 지원 여부, 전자책 취소 가능 여부

---

## 요약

지원금/결제 로직이 실질적으로 작동하는 지점은 **도서상세(개인도서 계산 실시간 노출) → 장바구니(합계 표시) → 결제(복합결제 처리) → 환불(지원금 환수)** 흐름이며, 추천도서 목록/개인도서 목록은 배지·예상금액 노출 정도로 관여도가 낮음.

## 미확정 항목 종합 (개발/스토리보드 착수 전 확인 필요)
- [ ] 추천도서+개인도서 동시 신청 시 통제 정책
- [ ] 월 지원한도 리셋 기준의 고객사별 유연성 여부
- [ ] 환불/취소 시 회사 지원금 환수 기준
- [ ] 부분환불 지원 여부, 전자책 취소 가능 여부
- [ ] 기존 PG에서 단일 주문 2개 결제처(회사+직원) 지원 가능 여부
- [ ] 결제수단 종류
- [ ] 각 팝업/안내 문구의 확정 카피
