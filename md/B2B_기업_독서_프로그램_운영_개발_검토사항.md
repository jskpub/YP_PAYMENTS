# B2B 기업 독서 프로그램 운영 관련 개발 검토사항 (2026.09.11)

## [개요] B2B 기업 간략 요청사항
- **위탁 용역 개요**: B2B 기업 독서 프로그램 운영 관련 위탁 용역
- **운영 목적**: B2B 기업 및 직원 간 정산 프로세스 및 독서 서평 작성과 같은 시스템을 통한 운영
- **독서프로그램 운영 및 정산 기준**:
  1. **① (공통) 추천도서**: 월 1권 100% 지원 (*신청자 限*)
     - 종이도서로 월 1권 도서구입비 100% 지원
  2. **② (선택) 개인도서**: 종이도서 or 전자도서 중 택1 지원
     - 종이도서 선택자에 한해서 월 1권 도서구입비 50% (1만원 한도) 지원
- **결제 및 서평 요청사항**:
  - 추천도서와 개인도서의 결제방식이 달라야 함.
  - 개인도서의 경우 회사 50% 지원(1만원 한도), 차액 직원 결제방식이 구현되어야 함.
  - 추가로 추천도서/개인도서 별 독서 서평을 쓸 수 있는 공간 필요.

---

## 영풍문고 전략
- **제공 형태**: ① 임직원 독서복지 플랫폼 + ② 도서 구매/정산 시스템 + ③ 서평·독서관리 시스템 + ④ 운영대행을 통합 제공하는 형태

## 1. B2B 기업 요구사항을 시스템 관점에서 재정의

| 구분 | 추천도서 | 개인도서 |
| :--- | :--- | :--- |
| **대상** | 신청자 | 신청자 |
| **지원** | 월 1권 100% | 월 1권 50%, 1만원 한도 |
| **도서 유형** | 종이도서 | 종이도서 또는 전자도서 |
| **결제** | 회사 지원 100% | 회사 지원 + 직원 부담 |
| **직원 결제** | 불필요 | 필수 |
| **서평** | 필요 | 필요 |
| **정산** | B2B 기업 ↔ 영풍문고 | B2B 기업 ↔ 영풍문고 + 직원 |
| **핵심 시스템** | 추천도서 신청/구매 | 지원금 자동계산·복합결제 |

- **핵심(Flow)**:
  > “B2B 기업 임직원이 로그인 → 추천도서 또는 개인도서 선택 → 지원금 자동 적용 → 직원부담금 결제 → 배송/전자책 제공 → 서평 작성 → 회사 정산자료 자동 생성”

## 2. 준비해야 할 시스템

### ① B2B 기업 전용 임직원 페이지
- 일반 영풍문고 쇼핑몰과 별도로 B2B 기업 전용관을 구축
- **예시) B2B 기업 독서지원 프로그램 메뉴 구조**:
  - 추천도서
  - 개인도서
  - 나의 구매내역
  - 나의 지원금
  - 독서현황
  - 서평 작성
  - 서평 조회
  - 공지사항
  - 문의/CS
- **인증 연계**: B2B 기업 임직원 인증(B2B 기업 SSO → 영풍문고 독서플랫폼 자동 로그인)을 연계

## 3. 가장 중요한 "지원금 Rule Engine"

- **추천도서**:
  - 도서가격 18,000원 → B2B 기업 지원 18,000원, 직원 부담 0원
  - 월 1권 제한
- **개인도서 – 종이책**:
  - `회사 지원금 = MIN(도서가격 × 50%, 10,000원)`
  - 도서가격 18,000원 → B2B 기업 지원 9,000원 / 직원 부담 9,000원
  - 도서가격 20,000원 → B2B 기업 지원 10,000원 / 직원 부담 10,000원
  - 도서가격 30,000원 → B2B 기업 지원 10,000원 / 직원 부담 20,000원

## 7. 정산 시스템 (별도 설계)

월말에 자동으로 정산 데이터 생성

### B2B 기업 정산자료 집계 (예시)

| 항목 | 건수 | 금액 |
| :--- | :--- | :--- |
| **추천도서** | 2,800 | 50,400,000원 |
| **개인도서 회사지원** | 1,430 | 13,500,000원 |
| **총 지원금** | 4,230 | 63,900,000원 |

- 직원 결제분은 별도로 관리
- **직원 결제 계산식**: `도서가격 / B2B 기업 지원금 = 직원 결제금액` 으로 자동 산출

### "정산 데이터 구조" (월말에 정산 파일을 자동 생성)
- `Employee ID` → 직원 식별번호
- `Order ID` → 주문번호
- `Book ISBN` → 도서 식별
- `Book Type` → 추천/개인
- `Format` → 종이/전자
- `List Price` → 정가
- `Selling Price` → 판매가
- `Company Subsidy` → B2B 기업 부담
- `Employee Payment` → 직원 부담
- `Order Date` → 구매일
- `Refund Status` → 취소/환불
- `Review Status` → 서평 작성 여부

## 8. "환불" 정책

- **검토 시나리오**: 20,000원짜리 개인도서를 구매해서 B2B 기업 10,000원 / 직원 10,000원을 결제했는데 직원이 도서를 취소한다면? 회사 지원금 10,000원을 어떻게 회수할 것인지가 필요함. 또 추천도서를 받은 뒤 환불하는 경우도 마찬가지임.
- **체크사항**: 지원금 적용 도서의 주문취소·반품·환불 시 회사 지원금 환수 기준 확인 필요.

## 6. 핵심 기능 : 지원금 자동 계산
이번 개발에서 가장 중요한 기능이다.

### 6.1 추천도서
- **지원금 산정**: 지원금 = 판매금액 100%
- **예시**:

| 판매금액 | 회사지원 | 직원부담 |
| :--- | :--- | :--- |
| **15,000원** | 15,000원 | 0원 |
| **20,000원** | 20,000원 | 0원 |
| **30,000원** | 30,000원 | 0원 |

### 6.2 개인도서
- **지원금 산정**: 회사 지원금 = MIN(판매금액 × 50%, 10,000원)
- **예시**:

| 도서가격 | B2B 기업 지원 | 직원 부담 |
| :--- | :--- | :--- |
| **10,000원** | 5,000원 | 5,000원 |
| **16,000원** | 8,000원 | 8,000원 |
| **20,000원** | 10,000원 | 10,000원 |
| **30,000원** | 10,000원 | 20,000원 |
| **40,000원** | 10,000원 | 30,000원 |

- **개발 고려사항**: 이 기능은 단순 쿠폰 방식보다는 **지원금 정책 엔진**으로 개발하는 것을 권장한다. 향후 B2B 기업이 정책을 변경하더라도 개발을 다시 하지 않고 관리자가 정책값을 변경할 수 있도록 한다.

---

## 7. 복합결제 시스템
개인도서의 핵심이다.

- **예시 (25,000원 도서 구매 시)**:
  ```text
  도서금액             25,000원
  B2B 기업 지원금       10,000원
  직원 결제금액         15,000원
  ────────────────────────────
  최종 결제금액         15,000원
  ```
- **시스템 처리**: 회사 지원금 + 직원 결제금액을 하나의 주문번호로 관리한다.
- **결제 프로세스**:
  ```text
  상품 선택
   ↓
  지원금 자동 계산
   ↓
  회사 지원금 차감
   ↓
  직원 부담금 계산
   ↓
  직원 결제
   ↓
  주문 완료
  ```

## 8. 서평 시스템
서평을 단순 게시판으로 만들지 않고 독서활동 관리 기능으로 개발한다.

- **서평 항목**:
  - 도서명
  - 구매일
  - 독서완료일
  - 평점
  - 한줄평
  - 상세 서평
  - 공개/비공개
  - 등록일
  - 수정일
- **My Library**: 직원이 본인의 독서이력을 관리할 수 있도록 한다.
  ```text
  나의 독서
   ├── 구매한 책
   ├── 읽는 중
   ├── 읽은 책
   ├── 서평 작성
   └── 독서통계
  ```

## 10. 정산 시스템

### 월별 정산
시스템에서 월별로 자동 집계한다.

- **정산자료 항목**:
  - 사번
  - 직원명
  - 부서
  - 주문번호
  - ISBN
  - 도서명
  - 도서구분
  - 도서유형
  - 판매금액
  - 회사지원금
  - 직원부담금
  - 주문일
  - 배송상태
  - 환불여부
  - 서평작성 여부

- **정산 프로세스**:
  ```text
  주문 발생
   ↓
  지원금 계산
   ↓
  결제
   ↓
  배송/전자책 제공
   ↓
  취소/환불 반영
   ↓
  월말 마감
   ↓
  정산 데이터 생성
   ↓
  B2B 기업 검증
   ↓
  정산 확정
  ```

## 11. 환불/취소 관리
반드시 개발범위에 포함해야 한다.

- **예시**: 개인도서 20,000원 구매 시 회사 10,000원 + 직원 10,000원 결제 후 환불하면 양쪽 금액이 모두 원복되어야 한다.
- **정의 필요 정책 항목**:
  - 주문취소
  - 부분취소
  - 반품
  - 환불
  - 전자책 취소 가능 여부
  - 지원금 복원
  - 월 지원한도 복원

## 15. 반드시 별도 체크 및 유의 되어야 하는 항목
1. **① B2B 기업 SSO**: 측 API/SSO 개발 필요 여부에 따라 달라짐.
2. **② 전자책**: 전자책 공급사 및 DRM 정책에 따라 별도 개발 가능.
3. **③ PG 복합결제**: 기존 영풍문고 PG 구조에서 지원 가능한지 확인 필요.
4. **④ 개인정보/보안**: 측 보안심사 요구 수준에 따라 비용 증가 가능.
5. **⑤ 외부 시스템 연계**: B2B 기업 HR 시스템과의 API 연계 범위에 따라 달라짐. (작업 중 연계 시는 API로 처리 필요함)
